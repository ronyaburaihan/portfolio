01 / LIVE TRANSLATION

Turner: LiveVoiceTranslator

Android & iOS Dec 2025 — Feb 2026

Lead Mobile Developer · team of 5

Real-time voice, text and camera translation, built for both platforms from a single Kotlin Multiplatform codebase.

  • Shipped to Google Play and the App Store with ~80% of the code shared across Android and iOS.
  • Built live speech-to-text over WebSockets, on-device translation across 66 languages, and camera OCR with document export.
  • Secured the API with Firebase App Check and usage metering; monetized through RevenueCat subscriptions and AdMob.
Engineering notes +

The challenge

Translation is latency-sensitive, ML Kit is platform-specific, and billing, ads and analytics each demand separate store-compliant wiring. Five developers, two platforms, zero tolerance for a second-class iOS experience.

The approach

A shared KMP core for domain, data and state, with expect/actual seams into native ML Kit, camera, speech and TTS on each side. Room-backed history and an offline phrasebook keep it usable without a network, and one release pipeline keeps both stores in lockstep.

02 / AI KEYBOARD

ImproveType: AI-Powered Keyboard

Android & iOS Oct 2025 — Present

Lead Mobile Developer

A system keyboard with on-device AI rewriting, grammar correction, tone change and translation — shipped natively on both platforms.

  • Launched on both stores covering 52 languages, 76 keyboard layouts and 43 app locales.
  • Delivered grammar fix, rewrite, tone change and translation, plus glide typing and next-word prediction from a 111K-word dictionary.
  • Tuned the iOS keyboard extension to run inside Apple’s ~60 MB memory ceiling; hardened Android startup with baseline profiles and R8.
Engineering notes +

The challenge

An IME is among the most performance-critical components on a phone. On iOS a keyboard extension is killed outright past a ~60 MB memory ceiling — while still satisfying strict store policy and running AI across dozens of languages.

The approach

Multi-module Clean Architecture isolating the keyboard core, with a dynamic layout engine for language packs. Baseline profiles and R8 guard startup and frame budgets on Android; on iOS, lazily built panels, aggressive teardown between sessions, and an App Group plus Darwin notifications to reach the host app.

03 / IMAGE ENHANCEMENT

Image Enlarger: AI Photo Upscaler

Android & iOS Jun 2025 — Present

Senior Mobile Developer

AI photo upscaling, face restoration and background enhancement, metered by a credit quota and shipped to both stores.

  • Built on one Kotlin Multiplatform codebase with ~82% of the code shared, released on Google Play and the App Store.
  • Integrated a server-side AI pipeline for upscaling, face restoration and background enhancement, funded by ads and subscriptions.
  • Built an offline gallery with paging, crop and transform tools, a referral flow and an iOS share extension, covered by a shared unit-test suite.
Engineering notes +

The challenge

Upscaling runs server-side, so every result costs money and latency. The client had to meter a credit quota fairly, stay responsive while a job is in flight, and keep finished results available offline — on two platforms with one team.

The approach

A KMP core owning credits, job state and history, with SQLDelight paging the gallery so results survive a cold start. Platform seams handle picking, cropping and the iOS share extension, while ads and subscriptions top up the same quota through a single repository.

04 / SECURITY & INFRASTRUCTURE

TTBoost

Android Jul — Aug 2026

Senior Android Developer · security & API layer

Security, authentication and networking ownership on a mature 18-module Android product, shipped at version 9.0.

  • Rolled out Firebase App Check across every HTTP client, with token prefetch, failure classification and retry.
  • Hardened request signing against replay attacks, backed by a regression test suite, and added device integrity and root detection.
  • Migrated the client through four backend API versions (v3 to v6) with localized error handling.
Engineering notes +

The challenge

The app was already shipping at v9 with a large surface area and a backend mid-migration. Security work had to land without a rewrite, without invalidating live sessions, and while endpoints moved underneath it four times.

The approach

Centralised identity and signing into one interceptor chain, so every HTTP client inherited App Check and replay protection at once. A regression suite went in around signing before it was touched, then each endpoint version migrated behind the same seam with upstream failures mapped to localized messages.
